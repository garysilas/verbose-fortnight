# Component registry check

The shadcn.io MCP now answers. Compared its **React / Radix UI** registry entries for Button, Dialog, Sheet and Popover with this repo's `src/components/ui/` copies. Registry reference: [Button](https://www.shadcn.io/ui/radix/button), [Dialog](https://www.shadcn.io/ui/radix/dialog), [Sheet](https://www.shadcn.io/ui/radix/sheet), [Popover](https://www.shadcn.io/ui/radix/popover). This is a source and API comparison, not a claim that the repo is broken or that an automatic upgrade is safe. The registry's current examples target `radix-ui`, `tailwind-variants` and newer Tailwind syntax; this repo uses separate `@radix-ui/react-*` packages, `class-variance-authority`, Tailwind 3.3 and the shadcn `default` style.

| Primitive | Repo copy versus current shadcn.io registry | Design implication |
|---|---|---|
| Button | Repo `button.tsx` has four sizes, six variants, 2px ring and 40px default height. Registry has more granular sizes, loading state, click effect, `aria-invalid` treatment and a 3px focus ring; its default is 32px. | Keep the repo's 40px controls in the current flow; borrow the explicit loading/invalid/focus states only after a targeted accessibility pass. Do not paste the registry's 32px default into the touch UI. |
| Dialog | Repo `dialog.tsx` supplies title, description, overlay and close, but no exposed close/footer variant controls or built-in long-content sizing. Registry exposes configurable close, size and a mobile bottom-stick option. | For code export, retain a title and make long generated code scroll within a bounded dialog. Registry source depends on its preview-frame utility, so it is not a drop-in copy. |
| Sheet | Repo `sheet.tsx` has side variants, close, title, description, header and footer. Registry adds configurable close behavior, slot markers and compact motion. | A sheet with a fixed header and footer is a better mobile customizer shell than the current nested Vaul drawer plus fixed-position Customizer; use the existing Sheet primitive first, not a wholesale registry replacement. |
| Popover | Repo `popover.tsx` offers trigger/content and Radix positioning. Registry adds header, title and description parts, bounded viewport width and newer motion. | Use popover for a short single setting, not the entire 1,266px editor; this is a composition problem rather than missing primitive functionality. |

**Decision:** no registry files adopted or app code changed in this audit. The useful registry pattern is the Sheet's header/content/footer organization and the Dialog's explicit long-content handling, adapted to the repo's current dependency and Tailwind version by Forge when the workspace redesign is approved. `components.json` points to `src/app/global.css`, while the actual file is `src/app/globals.css`; that is a separate configuration issue to verify before running a component install command. The current registry is clearly a newer, different implementation family, not proof that every old copy should be replaced.
