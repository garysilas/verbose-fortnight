# Theme customizer visual direction

## Observed state (read-only baseline)

Evidence: [390 light](shots/390-light-home.png), [390 dark](shots/390-dark-home.png), [768 light](shots/768-light-home.png), [768 dark](shots/768-dark-home.png), [1440 light](shots/1440-light-home.png), [1440 dark](shots/1440-dark-home.png), plus [390 open editor](shots/390-light-customizer.png) and [1440 open editor](shots/1440-light-customizer.png). These are first-viewport captures, not full-page images. The mode was selected through the app toggle; browser color-scheme emulation alone is not the app's mode.

The 56px sticky header carries presets, Customize, code export and social links on desktop. At 390px it hides the brand and page navigation but keeps Customize, Copy, two social icons and mode toggle in one row. A large centered hero and two repository links precede a black promotional card for another theme product. Its screenshot of color controls looks interactive but is an image/link; the actual customizer is a separate header-triggered overlay. The real component/block previews begin below “See It in Action,” beyond the first viewport at all tested widths. The open editor is a 480px-wide fixed, internally scrolling column on desktop and a full-width, 85%-height drawer on mobile. It groups style, preset color, radius, mode, CSS-variable swatches and export. The panel itself is 1,314px scroll-high in a 946px desktop viewport and 1,266px in a 761px mobile viewport, so the final swatches require internal scrolling. Light mode does not become a light page: the promotional card stays black by explicit zinc/black classes and keeps white type; the preview mockup keeps its screenshot colors. The light hero heading is black, dark hero heading white. Overall this is polished enough at a glance, but the primary edit/preview loop is buried behind marketing and a detached panel.

## Direction: preview-first instrument, not landing page

Preserve the semantic shadcn color model and sample components; make the user's theme the protagonist. This is an editing surface, not a campaign. Do not add decorative gradients, texture or perpetual animation. Show a compact toolbar and immediately show live component previews with a plainly labeled editing affordance. Move the external AI-themed promotion below the workspace or into a secondary link; distinguish its static screenshot from the live editor. Retain author attribution below the workspace, not between editor and preview.

- **Typography:** use a purposeful but quiet developer-tool pairing: a 14px/20px UI sans for controls and body, 12px/16px mono for CSS variables/values and code, 20px/28px semibold workspace title, 16px/24px semibold section titles, 12px/16px medium field labels. Avoid a 48px marketing heading above the preview. Preserve readable wrapping and 4.5:1 normal-text contrast in both modes. Font choice should not change the theme preview's intended font; the workbench chrome and the specimen are distinct.
- **Spacing:** 8px base rhythm; 16px between control groups; 12px within a group; 24px workspace gutters on desktop, 16px tablet, 12–16px phone. Toolbar 56px high. Give preview cards 16–24px padding, but do not use large vertical gaps above them. No global horizontal overflow at 390px.
- **Color:** neutral workbench surfaces only—light canvas `#fafafa`, surface `#fff`, text `#18181b`, border `#e4e4e7`; dark canvas `#09090b`, surface `#18181b`, text `#fafafa`, border `#3f3f46`. These are chrome values, not exported theme values. Reserve the user's chosen primary for samples, active selections and focus; avoid a competing lime badge or a permanently black promo card in the workspace. Keep code and labels legible independently of the editable swatch color.
- **Motion:** 120–180ms ease-out for opening, closing and selection feedback; no animated layout movement during color editing. Honor `prefers-reduced-motion: reduce` by removing transitions and any reveal animation. Edits should update the specimen without a distracting flash.
- **Dark/light parity:** same information hierarchy, spacing, editable tokens and export action in each mode. Show the mode being edited, and ensure the preview and code correspond to that mode; keep both light and dark CSS output discoverable. Test foreground/background pairs, borders, focus rings, empty and error states in each mode. Do not invert a specimen just to decorate the workbench.
- **Panel layout:** at ≥1024px, use a persistent 320–360px editor rail next to a flexible preview (min-width 0), not a popover floating over the specimen. At 768px, use a 320px rail or a clear edit/preview switch if preview width would fall below 360px. At 390px, use a full-width sheet with a fixed 56px header and 56px export footer, independently scrolling controls between, and an explicit close affordance. Order: mode, preset/style, radius, semantic color pairs, export. Show both color value and role; do not rely on a swatch alone. Put the copy action once in the sheet and once in the closed-state toolbar, not multiple competing copies in one view.

This is a direction for Forge/Atlas, not authorization to change app flow. The user requested documentation only.
