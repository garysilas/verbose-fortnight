# Current UX findings — ranked

Observed on the running home page at 390, 768 and 1440px in both app modes. Screenshot names are under [`shots/`](shots/). A viewport screenshot ending at its bottom edge is **not** evidence that the page content itself is truncated. Findings below distinguish visible behavior, measured layout and source attribution; proposed fixes are not implemented.

| Rank | Observed problem and evidence | Causing file | One-line fix |
|---:|---|---|---|
| 1 | The editing/preview workflow is not visible at entry: hero, repo buttons and a black promotional card fill the 390px first viewport; the first live preview starts below “See It in Action,” while the real editor needs the header Customize button. [390-light-home.png](shots/390-light-home.png), [390-dark-home.png](shots/390-dark-home.png) | `src/app/page.tsx` (hero and section order), `src/components/email-subscribe.tsx` (promo) | Put a labeled live preview and its edit control directly after a compact toolbar; move promotional content below. |
| 2 | The promo's right-hand color-configuration image visually impersonates the editor, but is a linked `<img>` to an external tool, not editable controls. [1440-light-home.png](shots/1440-light-home.png), [1440-dark-home.png](shots/1440-dark-home.png) | `src/components/email-subscribe.tsx` | Label the image as an external product preview, or replace it with the actual live specimen. |
| 3 | Light mode leaves the prominent promo card black with white text, so the first viewport remains mostly dark even after the app's Light choice. [1440-light-home.png](shots/1440-light-home.png), [390-light-home.png](shots/390-light-home.png) | `src/components/email-subscribe.tsx` (`bg-black`, `text-white`, fixed zinc colors) | Use semantic workbench surface/text tokens or place the fixed-dark campaign below the editing workspace. |
| 4 | The desktop editor obscures the hero/preview as a fixed overlay rather than sharing the workspace; measured 480px wide, 950px tall at 1440×1000. [1440-light-customizer.png](shots/1440-light-customizer.png) | `src/components/theme-customizer.tsx` (`Customizer` fixed right rail inside popover) | Make the desktop editor a docked 320–360px rail with a responsive preview beside it. |
| 5 | At 390×900, the drawer begins at y=135 and is 765px high; its inner content is 1,266px tall, leaving the later CSS-variable controls accessible only through a long inner scroll. [390-light-customizer.png](shots/390-light-customizer.png) | `src/components/theme-customizer.tsx` (85% drawer and fixed scrolling Customizer), `src/components/customizer/color-picker-section.tsx` | Give the sheet a fixed header/export footer and scroll only the grouped controls, with collapsible semantic sections. |
| 6 | The 390px header omits both brand and Themes/Blocks navigation but retains two social icons alongside Customize, Copy and mode toggle; the latter takes 40px, so tool context loses priority to off-site links. [390-light-home.png](shots/390-light-home.png), [390-dark-home.png](shots/390-dark-home.png) | `src/app/header.tsx` (`hidden md:flex` brand/navigation and always-visible socials) | Keep a compact product identity and preview navigation on mobile; move social links to the footer/menu. |
| 7 | A second “Copy code” action appears inside the open editor while the header one remains visible; on mobile the inner “Copy” is far below the first sheet viewport, and the header “Copy” bypasses code inspection. [1440-light-customizer.png](shots/1440-light-customizer.png), [390-light-customizer.png](shots/390-light-customizer.png) | `src/app/header.tsx`, `src/components/theme-customizer.tsx` (`CopyCodeButton` rendered in both places, mobile direct copy) | Define one export flow with inspect/copy affordances and a persistent sheet footer. |
| 8 | The desktop promo consumes most of the hero while the previews only begin near the bottom of a 1000px viewport; “See It in Action” is measured at y≈836. [1440-light-home.png](shots/1440-light-home.png), [1440-dark-home.png](shots/1440-dark-home.png) | `src/app/page.tsx` (hero, promo, then `ThemesTabs`) | Replace the large hero with a 20px workspace title and pull `ThemesTabs` above marketing. |
| 9 | The customizer radius choice is visually hard to parse among five dense buttons, and preset/style/mode selections all use a heavier border with no consistent selected icon or state label. [390-light-customizer.png](shots/390-light-customizer.png), [1440-light-customizer.png](shots/1440-light-customizer.png) | `src/components/customizer/radius-section.tsx`, `style-section.tsx`, `mode-section.tsx` | Use a shared selected treatment with an explicit value and `aria-pressed` for each exclusive choice. |
| 10 | CSS-variable controls are swatches with tiny “bg”/“fg” captions, not visible numeric values; the color input has `name` but no matching `id` for its adjacent `htmlFor`, so role/value identification is weaker than the editor requires. [390-light-customizer.png](shots/390-light-customizer.png), [1440-light-customizer.png](shots/1440-light-customizer.png) | `src/components/customizer/color-picker-section.tsx` | Show role plus editable hex/HSL value alongside each swatch, and associate each visible label with its input. |

The black promo is not a broken image or missing CSS—it is explicitly styled that way. The apparent cutoff of lower rows in the screenshots is chiefly viewport framing plus panel scrolling, not proof that rows are unreachable. The browser also emitted repeated Recharts zero-size warnings on mode/viewport changes; this is an engineering follow-up in preview demo code, not a visual claim ranked above the user-facing issues.
